# 把回滚做成部署的一部分

## 三种备份不要混称

1. 关键原始分区：原机 ART/GPT/引导等；按设备唯一，永不公开。
2. 系统配置 checkpoint：network/firewall、认证、服务和项目源码；含凭据，应限制权限。
3. 代理附加备份：DNS、核心、规则、配置，以及停止核心期间复制的一致性缓存。

每次记录文件大小、远端和电脑 SHA256、gzip 完整性。正在变化的缓存不要直接宣称一致性；额外归档排除活动 cache，用停机副本。BusyBox tar 的可选参数不同于 GNU tar，实际支持 `-X 排除文件` 的环境不能照搬 `--exclude`。

checkpoint 存在不等于任何改动都自动可恢复。每次只写本次修改的 undo，验证语法与备份哈希，独立 guard 监控期限及 boot ID。部署 SSH 断开后计时器仍需运行。提交必须有独立验证文件，且在期限内；超时或意外重启触发回退。见 [transaction.sh](../reference/router/transaction.sh)。

不要杀掉测试主进程就当清理完成：使用其回滚入口，确认无 active transaction、专用 nft 测试表、临时连接/监听和服务。VPS 主机规则与云防火墙是两个层次；本次历史记录中，主机测速端口关闭已确认，云端两条临时规则删除未获得独立确认。不能写“全部云规则已清理”。

## 长期维护清单

- 小改动单变量；更换内核/固件先核对 CAKE ABI、ath11k 修复和分区空间。
- 重启验收用 boot ID、服务 PID、5 路认证/DHCP、规则表、10 CAKE、autorate、RPS/XPS、CN 三频、真实请求。配置中 enabled 不是运行成功证明。
- 高频遥测放 RAM、限量轮转，避免 eMMC 写放大；重启清空的日志提前保存。
- 单路认证退避恢复；不要全局清连接或重启所有账号处理一条故障。
- 固定版本和来源，定期人工检查安全更新；不自动升级原厂系统，不无审阅更新规则覆盖自定义项。
- 游戏/视频优先，达到体验目标后停止搜索参数边界。平均 CPU 余量不保证瞬时余量。

## 故障定位顺序

管理链路→物理 carrier→单路 EAP→单路 DHCP/网关→路由表/mark/NAT→DNS真实或FakeIP→队列计数→代理节点。每层都有明确的读回证据，避免把 DNS 错误误诊为无线或加速问题。

提交 issue 只提供脱敏版本、错误、发生条件及最小配置；不要贴完整 `/etc`、NetID、密码、订阅、密钥、ART、抓包或带令牌 URL。自动脱敏检查只能辅助，不能保证识别所有秘密。
