# 从单路认证开始

这份指南适合已有 OpenWrt / ImmortalWrt 路由器、准备尝试多账号接入的读者。

## 1. 核对设备和依赖

| 项目 | 开始前核对 |
| --- | --- |
| 接入 | 确认校区认证类型、MiniEAP 插件是否适用，以及可用于测试的授权账号。 |
| 固件 | 核对物理 WAN 与 LAN 设备名。准备 MacVLAN、nftables、支持策略路由的 ip 工具，以及适配该内核的 CAKE 和 IFB。 |
| 管理 | 保留有线管理连接、将配置备份到电脑，并准备在 WAN 断开时恢复。 |
| 现场脚本 | 阅读引用的服务、DHCP 回调和策略文件。Athena 专用的健康预算、游戏分类及无线服务需要额外配套实现。 |

[校区适配项目](10-references.md) · [参考脚本依赖](../reference/router/README.md) · [备份方式](09-operations.md)

## 2. 先打通一条线路

在物理 WAN 上建立一个桥接模式 MacVLAN，分配稳定且唯一的 MAC。让 MiniEAP 在该接口上完成认证，随后通过 DHCP 获得地址和网关。用绑定该接口的请求确认国内 HTTPS 能访问，再检查对应路由表的默认路由。

认证成功、DHCP 租约和请求可达是三项独立检查。某一步失败时优先核对该层的配置。账号文件和含地址的原始日志保留在本机。

## 3. 逐路增加并检查分流

为其他授权账号各自配置 MacVLAN、认证进程和路由表。接入 PBR 和防火墙 NAT 后，用多条独立连接确认它们实际走不同的 WAN。逐一测试线路退出与恢复时新连接的归属，避免把某条长连接的下载速度当作聚合速率。[接口、路由表与 mark](03-five-wan.md)

## 4. 逐项添加整形和可选功能

先使用每路上传 CAKE 与下行 IFB，再决定是否需要下载流表和游戏专线。每次调整后复测吞吐、满载时延、丢包和逐核 CPU。Athena 的脚本使用特定的设备名、nft 表和模块 ABI，按你的设备核对这些值。[整形与测量](04-cake-and-measurement.md) · [Athena 快速路径](11-athena-runtime.md)

已移植相同布局时，可运行只读检查脚本对照 WAN bucket、路由规则和 qdisc。对跨设备移植的问题，提交固件、接口命名、一个故障层的最小配置和复现步骤即可。[检查与回退](09-operations.md) · [报告问题](../CONTRIBUTING.md)
